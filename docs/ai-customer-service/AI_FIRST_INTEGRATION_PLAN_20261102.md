# AI 全交互闭环开发计划

日期：2026-11-02。Server 开工基线：`Dev / d82a1c7`。状态：A0～A7 已实现并增量部署；A5/A6 完整浏览器流程和 A8 受控故障已通过，终版长测约20分钟出现上游PROVIDER_ERROR，按用户新要求停止追加验收。真实身份来源、手机/物理声学和业务验收单列，见文末执行记录和 [本批交付记录](AI_FIRST_DELIVERY_20261102.md)。原完整计划与阶段证据保留，当前执行状态不修改下文的原始交付标准。

根据用户最新要求，当前开发顺序调整为 AI 优先：先把文字、多模态、实时语音与画面、工具、上下文、输出及 App 适配连接成完整流程，再安排新增人工客服能力。原始完整规划、既有人工功能与交付记录保留。

## 1. 目标与范围

目标路径：用户在同一 `conversation_id` 中发送文字、语音、照片、文档或短视频 → AI 理解输入 → 必要时受控调用工具 → 返回文字/语音及来源 → 继续实时语音和画面交流 → 暂停、打断、补充材料 → 结束实时会话后继续文字 → 刷新或断线恢复后仍有完整历史、证据和草稿。

“全 AI”指本项目对话与远程指导场景中的既定能力，支持格式和资源限额由明确能力矩阵限定，不代表默认支持所有文件格式或模型功能。

本阶段包含：

- 普通文字多轮、流式回答、停止、失败重试与历史恢复。
- 语音消息的“转文字后编辑发送”和“保留原声理解”两种输入。
- 图片/多图、PDF/TXT、录音、短视频/有声视频，以及用户授权的定位信息。
- 文字、多模态与实时语音中的工具查询、状态、结果和来源展示。
- AI 实时语音的手动/VAD、暂停、打断、文字注入、心跳及显式恢复。
- 授权的实时画面采样、通话中补充材料、跨模式上下文及历史媒体复用。
- 普通回答朗读、实时音频播放控制、只读领域技能与结构化建议。
- Kuikly 专用 Server 适配、必要的身份/续期、预算、故障处理与联合验收。

后移：新增转人工策略、客服排队/技能组/SLA、专家转接、人工工作台扩展、人工音视频运营、正式工单提交/派单、支付和设备危险控制。既有人工功能继续兼容并保留必要回归；AI 故障通过明确错误、有限重试或用户选择处理，不以自动转人工作为本期闭环前提。

ESP32 按独立的 [全 AI 设备计划](ESP32_AI_ONLY_DEVELOPMENT_PLAN_20261102.md) 并行接入。本文负责共享 AI 能力与 App/Web 主链路，不重复分配设备网关开发；共享工具、上下文与审计接口需在第一批协调。设备 MCP 与业务 `get_device` 查询保持不同含义。

## 3. 统一交互规则

### 3.1 普通消息与语音消息

草稿 → 私有上传/派生（如需）→ 消息持久化 → 模型与上下文选择 → 工具步骤（如需）→ 最终答复 → 文字/语音输出 → 历史与来源可重读。

上传完成、检查通过、消息已保存、模型已收到和回答完成分别显示。重试沿用原消息/任务标识，不产生重复用户消息和双份正式回答。

“转文字发送”经过 ASR 并允许用户编辑；“原声理解”保留音频证据并调用相应模型。转写不能代替原声分析，失败或超限不能自动截短、改走转写后声称已分析全部声音；保留原件并明确处理范围。

### 3.2 实时音频与画面

显式同意 → 新建 session/短票 → provider 就绪 → 用户开始听音 → 分轮理解/工具/回复 → 暂停、打断或结束 → 停止设备/远端任务 → 返回原会话。

连接成功、本机预览和模型实际收到输入分别验证。相机默认关闭；当前画面是受限采样，不把它称为已验证的任意连续视频能力。后台、换会话、撤权和失败时停止本机采集与播放。

### 3.3 通话中补充文字、图片和文档

文字保留“已保存/已注入/已确认”的区别。图片和文档先完成私有上传及持久化，再按冻结能力进入处理步骤。先实现显式暂停后的有序补充：停止采集并确认清空未提交音频 → 验证材料 → 直接支持的图像输入或独立感知步骤 → 当前轮次上下文 ACK → 用户恢复听音。

复杂媒体可生成有原始证据引用的感知结果，再由当前 AI 轮次继续答复。若后续开放边说边上传，需单列输入排序与打断竞态验收。不能直接移除 `REALTIME_TEXT_ONLY` 限制，导致普通 Worker 和实时 Worker 同时正式回答同一输入。

### 3.4 跨模式、恢复和身份

文字、附件、语音、工具和实时回复共用会话；run/session/response/call/attachment 保持各自身份。新输入由服务端维护轮次代次，旧结果不得推进新轮次。

断线先查权威状态并补拉；实时恢复沿用显式确认旧会话终态、创建新 session 和重新同意，不自动复用旧 PCM、开麦或开镜头。账号/租户/环境/来源变化后，旧回调和播放不能进入新上下文；草稿与历史按身份隔离。

| AI-A7 稳定性与运行控制 | P0，横贯各批 | 单轮/会话/用户预算、并发限流、故障、trace、依赖和用量 | 超额/故障有真实状态，重试有界；已知 usage 保留，未知不填零 |

### A0：优先冻结内容

- 输入格式、MIME、大小/时长、原始音频与 ASR、图像/视频帧限制、定位语义。
- 文本、实时音频、普通朗读、工具进度、类型化结果与引用等输出。
- 每个已配置模型的原生工具/多模态工具能力、codec/采样率、输出模式和实际账户权限；普通链路沿用已验证配置，模型型号升级独立验证。
- 用户输入、模型处理、工具等待、取消、终态和恢复的权威事件；大整数、版本/游标与旧客户端兼容规则。
- 能力开关、配置检查和真实 provider 探测分开；探测有边界与有效期，不把一次成功当持续可用保证。

### A2：多模态与工具组合

已验证原生组合的模型优先使用同轮协议。未通过时，可显式配置“受控感知 → 有来源的中间结果 → 文字 Agent 查询/回答”，各步骤保存模型、材料引用和真实用量。这是明确的编排方案，不是失败后偷偷换模型。

不直接删除现有多模态保护；先补真实 SDK、Schema、参数/来源授权和失败测试，再按开关启用。材料不可读、图片模糊或 ID 有歧义时询问用户；音频分析失败不以转写冒充原声结论。PDF 扫描页等能力未验证时明确提示不可提取内容，不伪造全文。

### A3：AI 记忆和取证

为 AI 会话单独建立有界摘要，记录覆盖的消息范围、版本、事实出处和附件引用；不直接复用客服内部摘要作为 App 可见记忆。当前会话内按需重取仍获授权的图片、文本、音频片段或视频时间点，并执行租约、归属、大小和处理预算检查。

区分用户陈述、材料可观察信息、工具核验信息及模型推测，业务陈旧值保留采样时间。摘要过期可以重建；摘要/取证取消后不得继续生成正式答复。跨会话长期记忆不自动共享。

### A4：实时执行关键约束

- 共用工具允许列表、Schema、来源授权、结果过滤和审计核心；新建真实 session/response/call/attempt 账本，不伪造普通 `ai_run`。
- Java 持久维护 `turn_generation`；speech started、新注入和打断及时废弃上一代工具结果。
- Python 建立有界异步工具任务，结果回到串行状态队列；等待网络不能阻塞心跳、VAD、用户输入和取消。
- 等工具不是 assistant completed；非终态 provider step usage 单独保存，保持一条逻辑回答。
- 匹配的 function result ACK 后，由 Java 再授权续答；执行、结果接受、回填、续答和发布均验证来源、具体 token、lease 和轮次。
- 沿用普通工具的严格单轮预算，并增加整个实时 session 的调用/结果/费用上限。

状态机细节以 [实时工具设计](REALTIME_TOOL_EXECUTION_DESIGN_20261101.md) 为基础，新增协议以 A0 冻结版为准。

### A6：音频输出与技能

普通回答朗读先评估复用现有 TTS provider；新增会话权限保护的适配，绑定消息版本和取消状态，不直接开放旧设备/管理接口。区分实时音频、录音附件和文本合成；不默认录制或长期保存实时会话全部音频。

客户端维护当前会话/消息的播放所有者，支持停止、重播和明确失败；切会话或失去授权时停止，旧播放不能覆盖新对话。首批技能聚焦材料识别、补问、证据归纳、只读查询和结构化建议，配置需有版本与工具边界。模型不能加载任意脚本或 URL；业务写入、人工服务和危险设备控制后移。

## 6. 外部依赖与里程碑

| 依赖 | 安排 |
| --- | --- |
| 真实订单/工单/设备业务 API | 不阻塞 AI 技术链路；保留现有只读 adapter，未配置返回真实失败，不编造业务答案 |
| Laravel 身份生产者 | 与 App 登录/续期并行对齐；真实来源、签名票据和撤销仍是 App 正式登录验收依赖，与订单 API 不同 |
| 暂无真实身份来源 | 独立环境使用明确的受控技术身份与无业务数据工具；不把管理账号或来源签名密钥放进 App，不据此声称真实 SSO 完成 |
| Android/iOS 设备 | Server HTTP、浏览器及真实 provider 可以先验证；实际采集/播放、权限、后台行为须分别真机验收 |
| 模型组合 | 已有授权配置先行；未配置、未开通、未验证或不支持时关闭该组合，不凭型号宣称支持 |

- **M1：Server 全 AI 技术闭环**。受控客户端/浏览器 + Java/SQL + Worker + 真实模型完成交互矩阵，使用无业务数据的技术工具。
- **M2：App 全 AI 使用闭环**。真实登录、输入、工具、实时语音/画面、播放及恢复通过，并验证来源到期、续期与撤销。M1 不等于 M2。
- **设备支线**按 ESP32 专项计划记录网关、设备语音/MCP 与声学证据，不以 App 验收替代。

真实业务查询在 API 可用后单独接通和验收，不影响非业务 AI 对话已有能力。

## 7. 协议和数据约束

继续在 `Dev` 开发；保留旧客户端、ESP32 和既有人工 API 的兼容。新增字段、路由和游标采用明确版本或能力协商，不静默破坏旧协议。

模型只提议工具，Java 决定权限、参数、执行、审计和公开字段。公开结果不得直接暴露内部 arguments/result_json、密钥、存储 key、模型 URL 或完整来源响应。只读技能和技术工具也必须有范围及预算。

展示状态、transport、收音、播放和页面显隐分别管理。每个消息/上传/命令/调用有稳定幂等标识；ACK 不确定时查权威状态，不无限重发、不自动改走旧 Laravel AI。

数据库仅做可审查的增量表/字段/索引迁移；不删除、清空或重新初始化现有数据库。验收使用新的独立测试库。修改前记录基线，迁移后核对原用户、历史和消息；新功能独立开关启用，回退不依赖清库。原始完整 18 节规划保持原文，本文件调整后续实施优先级。
