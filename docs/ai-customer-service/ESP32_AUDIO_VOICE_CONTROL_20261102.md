# ESP32 声音与语音退出修复

2026-11-02。用户已确认局域网版本可以唤醒，但播放卡顿，“退出、再见”等不能结束会话。本次在同一块 USB 主板和独立 canary 中处理，原 Dev 数据库及服务保留。

## 修复内容

- 自定义 MultiNet 运行期间，播放任务优先级从 4 提升至 6，Opus 编解码从 2 提升至 5，优先于识别任务的 3；采音优先级 8 保留。旧版实际日志出现解码最长约 540 ms、下行队列丢包累计 1321，明显超过每帧 60 ms 的预算。USB 屏幕镜像保持关闭。
- 在应用启动时向既有 MultiNet 模型追加“别说了、停止播放、退出、再见、退下吧、结束对话”六条口令。继续使用原三条唤醒资源，资源文件不变。
- 本地打断先清空播放队列，失效旧轮次，再通知网关；退出回到待机并停止上传麦克风音频。播放任务和主循环不等待网络发送。
- 网关在模型之前识别完整的停止/退出口令，包括重复、标点及礼貌说法。停止保留对话连接，退出终止生成并关闭会话，不生成“遵命、退下了”后继续收音。普通话语中的“不要退出、再见是什么意思、如何退出”等通过回归检查。
- 网关把三条唤醒名作为唤醒处理，不再为称呼本身生成长问候；设备在进入收听时播放本地提示音。
- 修复 WebSocket 新连接沿用旧接收时间的问题，避免空闲后唤醒立即再次重连。

## 安装中发现的旧版升级问题

2.5.3 在升级前重新查询 OTA，重新签发的临时下载票据导致完整 URL 不相等；新版比较经验证的同源、同一不可变发布路径，并使用新授权票据下载，继续校验清单、镜像版本、长度和 SHA256。

USB 崩溃栈实际解析到 `vApplicationStackOverflowHook`。2.5.3 的自动升级不能作为本次可靠安装途径。新版把激活与升级任务栈调整为 16 KiB，并将 4 KiB 下载缓冲移到有界堆分配，分配失败时停止更新。2.5.4、2.5.5 的试装指派已暂停，未将它们报告为成功安装。曾尝试的 LAN 票据兼容缓存已移除，入口恢复逐次转发 canonical Manager 响应。

最终候选 **2.5.6 已通过 USB 安装并由实际设备报告 healthy**。USB 维护先完整备份，校验已运行且 VALID 的 2.5.3，将相同镜像复制到 `ota_0` 并整片读回；只在确认复制一致后整理 OTA 选择数据，再使用原首板流程写入非活动 `ota_1` 和追加升级元数据。此路径保留 2.5.3 的芯片内回退镜像及原 2.5.2 的完整 Flash 备份，不烧录空白 NVS 的合并镜像。原 59 项非升级配置全部保留。
