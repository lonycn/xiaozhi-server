# P3 realtime AI execution contract (frozen v1)

## Additive VAD and external source update

The original v1 details below remain the **manual** protocol; its browser input/output allowlists and session/task examples are extended by this section. `manual` remains the default. `features.realtime-server-vad-enabled` defaults to `false`. `GET /api/v1/ai/realtime/capabilities` returns `turn_detection_modes` and `default_turn_detection_mode`; session creation accepts `turn_detection_mode: "manual" | "server_vad"`. The stored Session and claimed worker Task carry that immutable mode. End the current session before changing modes.

In `server_vad` mode, an explicitly consented user starts and stops capture through browser frames `listening.start` and `listening.stop`; the worker emits `listening.started`, `listening.stopped`, `speech.started` and `speech.stopped` in addition to the v1 output allowlist. Stop sends `input_audio_buffer.clear` to the provider and only acknowledges `listening.stopped` after the real clear event. Automatic provider VAD commits the speech and starts its response, so an automatic audio turn does not use the manual `audio.commit` or manual `response.create` sequence described below. Speech during a response flushes local playback, while canonical cancellation awaits real provider termination. Ready, discovery and reconnect do not automatically activate the microphone.

While listening, text injection remains queued; after pause and the clear acknowledgement it may be dispatched under the existing provider item correlation and acknowledgement rules. Saved text is not the same as provider acknowledgement, and uncertain dispatched text is not replayed. The original limits, authorization checks and manual workflow remain applicable as described below.

External AI media requires the independently default-off `features.external-realtime-media-enabled` gate as well as the existing feature gates. Java captures and binds both external source session and the specific Bearer, checking them on requests and worker callbacks. Logout, source revocation, expiry, issuer or account loss terminates the affected authorization; another Bearer cannot take over the old media session. Follow [external media and VAD operations](EXTERNAL_MEDIA_VAD_OPERATIONS.md) for the exact external paths, cleanup limits and verification boundaries.

2026-10-30. Additive to B1–B5; existing conversation/message/history and human LiveKit APIs remain authoritative. Default `features.realtime-ai-enabled: false`. This Java API uses an independently authenticated Python WebSocket bridge, never a provider credential in the browser. No second production AI transport is introduced.

## Public HTTP API

All paths below are under `/api/v1/ai/realtime`, require the existing authenticated conversation owner, enabled account, and strict JSON (unknown fields rejected). IDs are strings; all counts/sequences/epochs/limits are JSON numbers even under the existing Long serializer. Times are ISO UTC strings. No client-provided actor, assistant content, provider event, provider URL, tool result or secret is accepted.

- `POST /sessions`: `{conversation_id,client_session_id,consent:{microphone:true,camera:false}}`. Explicit opt-in; owner and `AI_ACTIVE` only. Idempotent same key+body; changed body 409. One nonterminal session/conversation. Cancels unfinished B2 runs, raises conversation control_epoch, snapshots context_seq. Returns Session. Starting/ending never clears history or changes human mode.
- `GET /sessions/current?conversation_id=...`: Session or null. `GET /sessions/{id}`: owner only, including terminal state.
- `POST /sessions/{id}/connect-ticket`: `{expected_epoch}` => `{session_id,control_epoch,websocket_url,ticket,expires_at}`. URL contains no token/query. Ticket is opaque, 30 seconds, single use; only its SHA256 is persisted. At most one unused ticket; issuing another expires prior tickets. Send first WS body `{type:"connect",ticket:"..."}` within five seconds. Do not use a Bearer or ticket in URL. No reconnect/resume of an existing consumed session: make a new session after terminal failure.
- `POST /sessions/{id}/messages`: `{expected_epoch,client_message_id,text}` => `{message:<existing Message>,injection:<Injection>}`. At most 8000 characters. Java saves text first using the same conversation send transaction, queues one immutable injection, and skips B2. Normal conversation text sends while RT exists use the same hook. Media/location parts while RT exists return 409 `REALTIME_TEXT_ONLY`; drafts remain client-owned. Identical message retry returns its prior injection. GET `/sessions/{id}/injections?after=0&limit=50` returns existing CursorPage (numeric cursor).
- `POST /sessions/{id}/interrupt`: `{expected_epoch,client_command_id,response_id}` => Command. The response must be the current unfinished response. Idempotent same command+body. Immediately marks turn interrupting (late deltas rejected); worker flushes playback, cancels provider response, then reports authoritative cancellation. Already accepted partial text remains canceled in history.
- `POST /sessions/{id}/end`: `{expected_epoch}` => Session. Atomically ends session, invalidates tickets, fails queued/unconfirmed injections, cancels unfinished assistant messages; normal text B2 can resume. Same terminal epoch retry returns terminal Session.

Session: `{id,conversation_id,status,control_epoch,model,consent:{microphone,camera},provider_session_id,last_event_sequence,active_response_id,active_message_id,error_code,created_at,connected_at,ended_at}`. Status `pending|connecting|active|ended|failed|expired|canceled`; only provider `session.updated` produces active. A WebSocket connection alone never means active.
Injection: `{id,session_id,message_id,sequence,status,provider_item_id,error_code,created_at,acknowledged_at}`; status `queued|dispatched|acknowledged|failed`. Before acknowledgment, the legacy `provider_item_id` field carries Java's requested item ID; an acknowledged injection carries the real provider-assigned ID. The original request ID remains reconstructible as `rt-inject-<injection_id>` and is verified separately in the callback. A failed injection never removes its accepted message. Lost command confirmation after 15 seconds fails the session as COMMAND_UNCONFIRMED (heartbeat can return active=false); it does not falsely declare the provider canceled. There is no automatic resend after dispatch, because provider acceptance may be ambiguous.
Command: `{id,session_id,response_id,type,status,error_code}`; type `interrupt`, status `queued|dispatched|acknowledged|failed`.
Errors use existing HTTP Result `{code,msg,data}`; 401 account/auth, 404 resource/feature disabled route, 409 epoch/lease/order/state, 503 bridge config incomplete. No provider payload/secret is returned.

## Worker HTTP API

Prefix `/internal/realtime-worker`, dedicated `X-Realtime-Worker-Key` (at least 32 characters), unrelated to AI/media/user/server keys. Read via Environment in early Shiro creation. Every method is POST and returns Result; empty data means no task. HTTP request timeout <=3 seconds; heartbeat every 2 seconds. A lease/auth/epoch/order conflict or heartbeat active=false must immediately cancel provider reads/writes, close provider WS and browser WS, and cancel background tasks. No input/audio/output may continue after failure. Bounded stop target <=6 seconds (poll + timeout + close), independent of lease TTL. No long-lived DB transaction during any external I/O.

- `/consume`: `{ticket,worker_id,server_id}`. The worker only calls after first browser connect frame. Atomically single-use consumes ticket and claims a 12 second lease. Response Task:
`{session_id,conversation_id,control_epoch,lease_token,server_id,lease_seconds:12,model,consent,context:[{role,content}],context_seq,limits:{heartbeat_seconds:2,max_session_seconds:1800,max_audio_chunk_bytes:65536,max_audio_turn_bytes:1920000,max_frame_bytes:190000,max_frame_pixels:921600,min_frame_interval_ms:1000,max_event_text_chars:16000,max_output_chars:128000},input_audio:{encoding:"s16le",sample_rate:16000,channels:1},output_audio:{encoding:"s16le",sample_rate:24000,channels:1}}`.
Worker/server IDs match `[A-Za-z0-9_.:-]{1,100}`. Context <=40 messages/64000 chars, no secrets/URLs/tool execution. Text/images in previous attachment context are explicitly omitted markers, not fabricated media content. `context_seq` fixed at start, so subsequently queued text is never included twice.
- `/sessions/{id}/heartbeat`: `{lease_token,input_busy:<strict boolean>}` => `{active:true,lease_seconds:12,injections:[{id,message_id,text,provider_item_id}],commands:[Command]}`. Rechecks enabled config, owner status, mode, control epoch, token and unexpired lease before extending. When active, input_busy=false, and no response is in progress, atomically dispatches at most one queued injection; never redelivers a dispatched injection. Worker must serialize input with provider events; don't inject while its audio turn/response is in flight. Dispatching is not provider acceptance. Command dispatch is also once; loss ends as failed, not a fake ACK.
- `/sessions/{id}/events`: Event envelope below. Every canonical event is derived from the worker's authenticated provider connection, never browser JSON. Body requires `{lease_token,sequence,provider_event_id,type}` plus type-specific fields. Sequence strictly previous+1; an identical previously stored event ID+body is idempotent, changed body/ID or gaps return409. Bound provider_event_id to 200 safe ASCII chars. Recheck account/mode/epoch/lease before dedupe or any writes. A callback from the old lease/epoch cannot insert messages or usage. No audio base64 or frames in Java callbacks.

Event fields (all optional fields not listed for that type must be absent/null):
- `session.ready`: `provider_session_id` (from real session.updated; max200 ASCII).
- `input.committed`: `provider_item_id` (real input_audio_buffer.committed). Reserves one user message with status transcribing and no invented text; Java ACK must precede response.create. If ASR arrived first, reuses its already completed message without resetting it.
- `input.transcript`: `provider_item_id,text` (from conversation.item.input_audio_transcription.completed). Fills the same reserved `user` message, or creates it if ASR arrived first; source recorded as provider_audio_transcription. May arrive after response starts; item is immutable, replay with new event ID rejected. Empty final transcript is status failed with no fabricated content. A pending transcription becomes failed if the session ends; its row remains for honest history.
- `response.started`: `response_id` (real response.created), creates a single queued/streaming assistant message. Only one unfinished response/session; no arbitrary tool/function output.
- `response.delta`: `response_id,text` (real response.audio_transcript.delta or response.text.delta, choose one consistent representation per response). Nonempty <=16000 chars; cumulative128000. Appends same assistant message. Rejected after interrupt is recorded.
- `response.completed`: `response_id,text,finish_reason,usage?` (real final transcript/text and response.done). Final text is authoritative, <=128000; finish_reason `stop|length|content_filter|tool_calls|unknown`; usage `{input_tokens,output_tokens,total_tokens}` nonnegative JSON integers, or null if absent/incomplete. Persist actual usage once per response; never estimate. `tool_calls` means unsupported; no business execution or invented tool result. Terminal partial interrupted text cannot be overwritten by later complete text.
- `response.canceled`: `response_id,usage?` (real provider termination: canceled, or response.done after an already issued persistent interrupt (cancel/completion race)), preserves already accepted partial text as canceled. No synthetic completed reply.
- `injection.ack`: `injection_id,request_item_id,provider_item_id` from matching real conversation.item.created. The callback includes required `request_item_id` (the immutable ID dispatched by Java) and `provider_item_id` (the real ID returned by the provider). Java verifies the request ID against this dispatched injection, rejects reused provider IDs, then saves the actual provider ID; it does not require the provider to echo the requested ID. The worker must correlate one pending request using the exact echoed text, message role/content type and the real `previous_item_id` predecessor; order alone is insufficient. Message text is already in Java and is not copied back. ACK only after provider acceptance, then response.create; no ACK on outbound socket send.
- `injection.failed`: `injection_id,error_code`; allowed errors `PROVIDER_REJECTED|INJECTION_UNCONFIRMED|PROVIDER_TIMEOUT`.
- `command.ack`: `command_id,response_id`; only after real provider cancellation confirmation, matching canceled/completed turn, never just outbound cancel send.
- `session.error`: `error_code` in `PROVIDER_AUTH|PROVIDER_RATE_LIMIT|PROVIDER_TIMEOUT|PROVIDER_UNAVAILABLE|PROVIDER_ERROR|WORKER_ERROR|CLIENT_DISCONNECTED|UNSUPPORTED_TOOL|INPUT_LIMIT`. Session fails, existing partial replies canceled and injections fail. No raw provider error messages.

Success returns `{sequence:<number>,session:<Session>,message_id:<string|null>,message_status:<string|null>}`. Worker preserves an outbound callback until ACK and retries identical ID/sequence/body; never advances sequence on uncertain failure. Canonical provider events may be buffered to impose response.started before delta/final; Java rejects invalid order. Do not replay unconfirmed provider text injection after bridge restart.

## Browser ↔ worker WebSocket v1

After connect authentication, worker returns `{type:"connected",session_id,control_epoch}` (connecting), later `{type:"ready",session_id,control_epoch}` only after Java acknowledges real provider session.updated. Input allowlist: `{type:"audio.append",audio:<base64>}`, `{type:"audio.commit"}`, `{type:"frame.append",image:<base64>,mime_type:"image/jpeg"}`. Audio raw mono s16le16k, per append64KiB, per manual turn60 seconds/1.92MiB. Frame only with camera consent, max190000 bytes (base64 <=256000 bytes), decoded<=921600 pixels, >=1000ms spacing and only after some audio has been appended in that turn. No video file or URL accepted; this is sampled images accompanying audio, not a claim of full video transport. Worker may expose explicit `{type:"error",code}` and close on limit violations. No arbitrary provider events, session.update, tools, assistant text or text injection via WS.
Output allowlist: `connected|ready|audio.delta|transcript.delta|response.started|response.completed|response.canceled|injection.status|error|ended`; identifiers tie to the persisted message/response. Audio output is raw s16le24k; chunk streaming requires a currently valid lease. Persist canonical transcript through Java before exposing corresponding transcript/final status. Usage comes only from Java-ACKed provider completion; missing usage null. Worker flushes audio on interrupt and canceled session. Browser authoritative history and recovery use ordinary messages/events API. No binary/media persisted by Java for this phase.

## Lifecycle, persistence, and privacy

Six append-only tables: ai_realtime_session, ai_realtime_ticket, ai_realtime_event, ai_realtime_turn, ai_realtime_injection, ai_realtime_command. Only row status updates/INSERTs; no business DELETE/TRUNCATE. Original changesets remain immutable. Expiry sweeper (also runs with realtime flag off while conversation foundation remains on) cancels pending/connecting60s, leases12s, sessions1800s; queued text waits<=60s, dispatched ACK<=15s. Worker restart does not resume old provider sessions. No active-session reclaim: expire, retain transcript and start a new explicit session. SQL session active-slot prevents duplicates, lock order owner account → conversation → session → tickets/turns/tasks. Current account locking reads avoid repeatable-read stale auth; use shared TimestampColumnMapRowMapper for all datetime Maps.

B2 mutual exclusion is checked on send, retry and claim under the same conversation lock. B1 transition cancels RT in its existing transaction; account disabling is checked every callback/heartbeat and cleanup sweep, so no late event can pass even before asynchronous stop. Human B5 media stays independent. End RT only restores ordinary text execution availability and does not switch manual support state.

Official references (verified 2026-10-30): [Qwen Omni realtime guide](https://help.aliyun.com/en/model-studio/realtime), [client events](https://help.aliyun.com/en/model-studio/client-events), [server events](https://help.aliyun.com/en/model-studio/server-events). Modern qwen3.8 session.update uses audio.input/output.format `{type:"pcm",sample_rate:16000/24000}` and explicit input transcription. Wait session.created→session.update→session.updated before input. Manual input uses audio append/optional bounded image append→commit→real committed event→Java input.committed ACK→response.create. Provider credentials/config belong exclusively to Python worker; Java never reads or returns them.

Canonical worker event endpoint alone skips the existing XSS JSON rewriter, reads <=1MiB before parsing, and preserves literal provider text. Rendering uses plain text. B3 old ai-worker delta is a separately identified legacy exact-route text-rewrite risk; no broad XSS bypass is added.

Interrupt race rule: a delta rejected with409 RESPONSE_INTERRUPTED_OR_TERMINAL is discarded without advancing callback sequence, playback is flushed, and the worker immediately polls heartbeat for the persistent interrupt. This specific fence is recoverable; lease/auth/epoch/order/reused conflicts remain fatal. A response.completed receipt whose message_status is canceled must emit only response.canceled to the browser, never the rejected final transcript. If provider response.done already arrived before command dispatch, cache its response ID and ACK the later command from that real termination evidence without sending a second provider cancel.

Limits additionally bound each session to 200 assistant responses, 400 total turns and 50000 canonical events. These are safety ceilings, never estimated provider usage. Camera permission is fixed at explicit creation; increasing permissions requires end/new consented session. Stopping local camera sampling is always available.

Injection and interrupt ACK deadlines (15 seconds after dispatch) are rechecked inside each callback, independently of the expiry sweep. Connecting has a 60-second creation-to-ready deadline even if a worker keeps renewing its lease.

## Real-provider ACK clarification (2026-10-30)

The isolated Java→Python→Bailian R6 bridge observed Qwen3.8 allocating a fresh `item_*` ID despite the requested `item.id`, without echoing the client event ID. Requiring ID equality caused an honest unconfirmed-injection timeout. `request_item_id` therefore binds the Java dispatch while `provider_item_id` always records the real accepted ID after ACK (bounded to the existing injection column's 100 ASCII characters). A single pending request, exact `user/input_text` echo and real predecessor anchor are all required. Context uses the same echoed-role/text/predecessor correlation without creating duplicate Java messages. Unknown, changed, out-of-order or uncorrelatable ACKs fail closed; repeated accepted ACKs never rewind the anchor or trigger another response. A provider input-audio item may be created while audio is still appending, before manual commit; that does not permit `response.create` before the real committed event and Java ACK.
